# PROJECT WORLD — 아키텍처

이 문서는 전체 목표(AI 모험가가 살아가는 상용 수준 2D 샌드박스 MMORPG)를 기준으로 한 구조 설계와,
각 PHASE에서 실제로 구현된 범위를 구분해 기록합니다(현재 PHASE 4 완료).

## 1. 설계 원칙

1. **시뮬레이션과 렌더링의 분리** — 월드 데이터, 월드 생성, 물리, 성장 공식은 `packages/shared`에 있으며
   Phaser/DOM에 의존하지 않습니다. 같은 코드가 PHASE 6에서 서버의 권한 있는(authoritative) 시뮬레이션이 됩니다.
2. **결정론** — 모든 절차적 콘텐츠는 시드에서 파생되고(`deriveSeed`), 물리는 고정 스텝(60Hz)으로 진행합니다.
   같은 시드 + 같은 입력 → 같은 결과. 서버 검증·클라이언트 예측·리플레이의 전제 조건입니다.
3. **데이터 기반** — 타일·오브젝트·직업·이동 튜닝·지역은 `packages/shared/src/data/*`의 데이터입니다.
   새 타일/직업 추가 = 데이터 한 항목 추가 (+ 클라이언트 아트 레시피 한 항목).
4. **게임 ↔ UI 경계** — React UI는 Phaser 객체를 만지지 않습니다. 게임은 스토어에 (스로틀링해서) 쓰고,
   UI는 `GameBridge`의 명령/조회만 사용합니다.
5. **교체 가능한 아트** — 모든 그래픽은 현재 코드로 생성(절차적 픽셀 아트)되지만, 텍스처 키/프레임 이름
   규약(`render/textureKeys.ts`)을 따르므로 손으로 그린 아틀라스로 그대로 교체할 수 있습니다.

## 3. 렌더링 구조

카메라 4개, 레이어 4개로 구성됩니다.

| 카메라  | 레이어       | 내용                                            | 비고                           |
| ------- | ------------ | ----------------------------------------------- | ------------------------------ |
| bg      | bgLayer      | 하늘 그라디언트, 별, 해/달, 구름, 4단 패럴랙스  | 시간대 틴트, 조명 미적용       |
| world   | worldLayer   | 청크 RenderTexture, 오브젝트, 캐릭터, 먼지/낙엽 | **LightingPipeline 포스트 FX** |
| overlay | overlayLayer | 불빛 글로우, 반딧불, 불씨                       | 발광체(조명 미적용, ADD)       |
| labels  | labelLayer   | 이름표 (추후 데미지 숫자)                       | 1× 배율 — 픽셀 폰트 원본 크기  |

- **청크 렌더링**: 비어 있지 않은 청크마다 512×512 RenderTexture에 한 번 굽고(`batchDrawFrame`),
  `chunk.version`이 바뀔 때만 다시 굽습니다(경계 타일이 바뀌면 이웃 청크 버전도 올라가 오토타일이 갱신). 카메라 주변만 스트리밍하며(프레임당 최대 2개 베이크,
  히스테리시스 2청크), 하늘만 있는 청크는 텍스처를 만들지 않습니다.
- **오토타일**: 4방향 연결 마스크(16) × 변형 3. 같은 병합 그룹(흙·잔디·돌)은 외곽선 없이 이어지고,
  돌은 "프린지" 오버레이로 흙 위에 들쭉날쭉한 경계를 그립니다.
- **조명**: `LightGrid`가 타일 단위 RGB 빛을 전파합니다(하늘 = 환경광, 모닥불 = 점광원, 타일별 `lightPass` 감쇠,
  4방향 스윕 2회). 결과를 작은 캔버스 텍스처(타일당 1텍셀, 이중선형 샘플링)로 올리고 world 카메라의
  포스트 FX 셰이더가 곱합니다. 하늘 카메라에는 적용되지 않으므로 배경이 이중으로 어두워지지 않으며,
  값 범위 0–2라 광원이 주변을 밝게(overbright) 만들 수 있습니다.
- **횃불**: 타일 데이터의 `light`가 조명 그리드에 광원으로 들어가고(깜빡임 포함), 불꽃 애니메이션과
  글로우는 `TorchRenderer`가 발광 레이어에 그립니다(움직이는 타일은 청크 텍스처에 굽지 않음).
- **도구 사용 연출**: 사용 중에는 앞팔이 없는 몸 시트 + 24방향 팔 스프라이트 + 손에 든 아이템으로 전환해
  다리는 달리기 애니메이션을 유지하면서 팔만 커서 방향으로 휘두릅니다. 채굴 균열 4단계, 파편 파티클,
  나무 흔들림/쓰러짐, 드롭 아이템 스프라이트.
- **타이밍**: Phaser의 `smoothStep`을 꺼서 실제 프레임 시간을 사용 — 프레임 저하 시 슬로 모션이 아니라
  고정 스텝을 따라잡습니다(PHASE 6 서버 동기화 전제).
- **픽셀 퍼펙트**: 화면 높이에 맞춘 정수 배율(설정에서 1–4× 수동 선택 가능), 카메라 좌표를 화면 픽셀 격자에 스냅.

## 4. 샌드박스 규칙 (PHASE 2)

모든 월드 상호작용은 `sandbox/interaction.ts`의 `applyItemUse()` 하나로 검증·적용됩니다. 클라이언트는 지금
이 함수를 직접 호출하고, PHASE 6에서는 클라이언트가 "(tx, ty)에 사용" 의도만 보내고 서버가 같은 함수로
판정합니다.

- **판정 순서**: 월드 범위 → 쿨다운(도구 속도) → 사거리(몸 중심 → 타일 중심) → 설치/오브젝트/타일.
- **채굴**: 타일 `durability`(HP)에 도구 `power`가 누적, 3초 내 같은 대상을 다시 치지 않으면 초기화.
  `minPower` 미달(철광석 ← 낡은 곡괭이) → `tool_too_weak`. 나무·모닥불이 서 있는 땅은 `supports_object`.
  잔디는 흙을 드롭, 지지대를 잃은 풀/꽃과 횃불은 함께 떨어짐.
- **설치**: 빈 칸 + 인접한 고체/발판 또는 배경 벽이 있어야 함(횃불은 좌/우/아래 고체 또는 벽).
  고체 블록은 캐릭터 몸과 겹칠 수 없음. 풀/꽃은 덮어쓰기 가능, 덮인 잔디는 흙으로 변함.
- **오브젝트**: 나무(도끼, HP), 바위(곡괭이), 풀·덤불·꽃·버섯(맨손 포함 아무 아이템) — 드롭은 확률·수량 데이터.
- **인벤토리**: 40칸(앞 10칸 = 단축 슬롯), 스택·이동·병합·스왑, 인벤토리 창의 커서 스택(좌클릭 집기/놓기,
  우클릭 절반/하나). 저장 데이터를 불러올 때 모르는 아이템·비정상 수량은 제거/보정.
- **제작**: 재료 확인과 결과물 공간 확인 후 원자적으로 적용. 작업대 등 제작대는 레시피 `station` 필드로 확장.
- **드롭**: 물리(중력·충돌)를 가진 엔티티로 튀어나오고 0.35초 후 5.5타일 안에서 플레이어에게 끌려와 수집.
- **입력**: 마우스 클릭은 다음 시뮬레이션 틱이 소비할 때까지 버퍼링되고, 도구 쿨다운 중의 클릭도
  최대 0.35초(시뮬레이션 시간) 대기해 손실되지 않음.

## 5. 전투·RPG (PHASE 3)

모든 전투 규칙은 `packages/shared`에 있고 엔진·렌더링과 무관합니다(PHASE 6 서버에서 그대로 실행).

- **행동 = 데이터**: 기본 공격·스킬·몬스터 공격 모두 `ActionDef` 타임라인(`hit`·`projectile`·`dash`·
  `teleport`·`buff`·`zone` 이벤트)입니다. 새 스킬은 대부분 `data/skills.ts`에 데이터만 추가하면 됩니다.
  레벨별 수치는 `[기본값, 레벨당 증가]` 쌍(`scaled()`), 공격 속도는 타임라인 시간을 나눕니다.
- **ActorCombat**: 입력 의도(`CombatIntent`: 공격 누름/유지, 조준점, 스킬, 회피)를 받아 콤보 창·캔슬 지점·
  입력 버퍼·차징·대시를 처리하고 모터에 이동 보정(`MotorOverride`)을 돌려줍니다. 플레이어와 PHASE 4 AI
  모험가가 같은 클래스를 씁니다(AI는 두뇌가 의도를 만듦).
- **CombatWorld**: 히트 윈도(소유자를 따라다니는 판정 영역, 대상별 1회 또는 간격 재타격), 투사체(중력·유도·
  관통·폭발·지면 이동), 장판, 상태 이상 틱. 피해 공식: `공격력 × 배율 × (0.9~1.1) × 100/(100+방어) ×
레벨 차 보정 × 받는 피해 × 약점 배율 × (치명 시 1+치명 피해)`. 결과는 이벤트로만 나가고 렌더러는 읽기만 합니다.
- **능력치**: `computeCombatStats(성장치, 직업, 무기, 장비 보너스, 패시브+버프 수정치)` — 무기 종류가 주/보조
  스탯을 정합니다(검 STR/DEX, 활 DEX/STR, 단검 LUK/DEX, 지팡이 INT/LUK).
- **몬스터 AI**: 행동 FSM(외부 AI 서비스 없음). 모든 위험한 공격은 예고(telegraph) → 실행 → 회복(약점) 구조라
  조작 타이밍으로 대응할 수 있습니다. 보스는 거리 기반 패턴 선택, 체력 50% 이하 격노.
- **생성 규칙**: 플레이어 주변 26~46칸 링(화면 밖), 지역(지표/지하/심층)·시간대별 가중치, 시작의 언덕(±34칸)과
  횃불 7칸 이내 제외, 지역별 상한, 80칸 밖 6초 후 소멸.
- **클라이언트 표현**: `CombatPresenter`가 시뮬레이션 이벤트를 받아 몬스터/투사체 스프라이트, 무기 궤적(히트
  윈도 타이밍에 맞춰 예약), 데미지 숫자, hitstop, 흔들림, 잔상, 레벨업 연출, HUD 스토어를 갱신합니다.

## 6. AI 모험가 (PHASE 4)

외부 AI 서비스·LLM 없이 자체 게임 로직으로 구현했습니다. 전부 `packages/shared`에 있어 PHASE 6 서버에서 그대로
실행됩니다. **AI는 플레이어와 같은 규칙으로 움직입니다** — 두뇌는 `CharacterIntent`(이동 입력·조준·공격·스킬·
회피·아이템 사용)만 만들고, 월드·전투·인벤토리 변경은 플레이어와 같은 `stepCharacter()` → `applyItemUse()` /
`ActorCombat` 경로로만 일어납니다. 순간이동·무적·아이템 생성 같은 AI 전용 지름길은 없습니다(추상 LOD 제외, 아래).

**계층 구조**

| 계층                      | 주기        | 역할                                                                                                        |
| ------------------------- | ----------- | ----------------------------------------------------------------------------------------------------------- |
| 관리(`housekeeping`)      | 1.5–2.5초   | 스탯 자동 분배, 전직·스킬 습득, 목표를 향한 제작, 더 좋은 장비 착용, 단축 슬롯 정리, 목표 갱신·완료 판정    |
| 판단(`scoreActions`)      | 약 0.5초    | 10개 행동의 효용 점수(성격·체력·목표·시간대·기억·위험) → 최고 점수 선택, 현재 행동 +0.12 가산(히스테리시스) |
| 행동(fight/gather/mine/…) | 매 틱(60Hz) | 경로 추종, 공격 사거리 유지, 활 차징, 스킬, 예고 공격 회피, 채굴 계단 파기, 물약                            |
| 이동(`PathFollower`)      | 매 틱       | 내비게이션 경로 재생 — 점프는 그래프가 검증한 입력 스크립트를 그대로 재생, 1.4초 끼임 시 재탐색             |

- **성격·목표**: 8특성 성격 → 생활 방식(사냥꾼·장인·탐험가), 선호 직업, 도주·물약 기준, 말투. 목표(`level`·
  `item`·`explore`·`slay`, 20분 제한)는 `knowledge.ts`가 아이템 출처(타일·오브젝트·몬스터 전리품·레시피)를 역추적해
  "철 검 → 철광석 → 지하 32칸 채굴" 같은 하위 작업으로 풉니다.
- **길찾기**: `NavGrid`는 1×3타일 몸이 설 수 있는 칸을 노드로, 걷기·자동 오르기·낙하·발판 통과·점프를 간선으로
  둡니다. 점프 간선은 실제 `CharacterMotor`로 5가지 입력(방향 세기 × 점프 유지 시간)을 시뮬레이션해 착지점을
  찾고 캐시합니다(타일 변경 시 주변 무효화). A\*는 확장 수 700으로 제한하고, 점프는 걷기로 막혔거나 목표가 위쪽/
  근처일 때만 탐색합니다. 틱당 경로 탐색은 1회로 제한해 프레임 스파이크를 막습니다.
- **기억·관계**: 사건 10종을 중요도와 함께 저장(최대 60개, 반감기 20분, 중요도 0.8 이상은 거의 잊지 않음).
  죽은 장소 근처는 위험으로 기억해 피하고, 자신을 도와준 플레이어(같은 몬스터를 함께 공격)에게는 호감도가
  오릅니다(관계 데이터 구조는 모험가끼리도 쓸 수 있게 되어 있으며 PHASE 5에서 확장).
- **공정성**: 몬스터는 첫 타격자가 10초간 소유(다른 모험가는 손대지 않음), 전리품은 처치 기여자가 8초간 우선권.
  시작 마을(±34칸)은 채굴 금지.
- **LOD** (`AdventurerDirector`): 플레이어 56칸 이내 최대 14명은 **완전 시뮬레이션**(엔티티·물리·전투), 76칸
  밖은 **추상 시뮬레이션**(1초 단위: 활동 선택 → 지표 높이로 이동 → 사냥은 DPS·몬스터 HP로 처치 수와 피해를,
  채굴·채집은 확률로 결과를 계산). 화면 안(36칸)에 추상 상태로 남은 모험가는 화면 밖으로 밀어내 "갑자기
  나타남"을 막습니다. 오프라인 시간은 최대 2시간을 10초 단위로 따라잡고, 새 월드는 8분을 미리 진행합니다.
- **클라이언트**: 30명의 외형 합성(1명당 약 260ms)은 Web Worker에서 하고 프레임당 텍스처 1개만 업로드합니다
  (워커를 못 쓰면 메인 스레드 대체). `AdventurerRenderer`가 `CharacterView`(플레이어와 같은 애니메이션·무기
  모션)와 이름표·말풍선을 그립니다. UI는 스토어(2Hz)로만 모험가 정보를 받습니다.
- **LLM**: 사용하지 않습니다. 대사는 말투 5종 × 상황 10종 템플릿(i18n). 추후 승인 시에도 LLM은 별도 모듈에서
  대사만 생성하고 게임 상태를 직접 바꾸지 못하게 합니다.

## 7. 저장 (브라우저 IndexedDB)

- `SaveStore` 인터페이스(IndexedDB 구현 + 메모리 대체). PHASE 6에서 서버 구현으로 교체.
- 월드: **수정된 청크만** RLE로 저장(`World.collectDirty()` 증분 저장, 5초 자동 저장 + 탭 숨김/닫힘 시 즉시).
  수정 안 된 청크는 시드로 재생성. 플레이어: 위치·인벤토리·선택 슬롯·탐험한 청크(월드맵)·플레이 시간.
- 메모리: 화면에서 6청크 이상 떨어진 청크 데이터는 언로드(수정된 것은 직렬화 상태로 보관 후 필요 시 복원).
- 형식 버전 필드(`CHUNK_FORMAT_VERSION`, `SAVE_VERSION`)로 마이그레이션. v2(PHASE 3)는 레벨·직업·스킬·
  단축키·장비·HP/MP를 저장하고, v1 세이브는 기본값 + 시작 무기·물약 지급으로 이전합니다. 불러올 때 모든 값을
  검증(모르는 스킬·아이템 제거, 레벨·수치 범위 제한)합니다.
- AI 모험가: 월드별 `${worldId}|adventurers` 키에 모험가마다 캐릭터 스냅샷(플레이어와 같은 형식)·위치·목표·
  기억·추상 활동을 저장합니다. 프로필(이름·성격·외형)은 시드에서 다시 만들어지므로 저장하지 않습니다.

## 8. 이동·물리 (CharacterMotor)

`stepMotor(state, input, grid, config, dt)` — 순수 함수, 고정 스텝.

- 지상/공중 가속·감속 분리, 반대 방향 입력 시 빠른 전환(turnAccel)
- 가변 점프 높이(조기 해제 시 속도 컷), 정점 체공(점프 유지 시 중력 감소), 낙하 중력 배수
- 코요테 타임 0.1s, 점프 버퍼 0.12s
- 1타일 자동 오르기(Terraria식) + 1타일 내리막 스냅 (애니메이션 깜빡임 방지, 뷰에서 부드럽게 보간)
- 단방향 나무 발판, `↓ + 점프`로 내려가기
- 이벤트(점프/착지 속도/스텝/발판 통과)를 뷰·FX가 소비

튜닝 값은 전부 `data/movement.ts`에 있으며 단위 테스트가 점프 높이·코요테·버퍼·스텝·발판·결정론을 검증합니다.

## 9. 절차적 픽셀 아트 파이프라인

모든 생성기는 DOM 없는 `PixelCanvas`(Uint32 RGBA)에 그리므로 테스트·오프라인 미리보기(`art:preview`)가 가능합니다.

- **캐릭터(paper-doll + IK 리그)**: 64×64 프레임, 신장 약 50px(5.5등신)의 현실적 비율.
  `Appearance`(피부·헤어 5종·눈·의상 실루엣[롱코트/재킷/판초]·내의·포인트색·하의·신발·모자[고글/후드]·
  스카프[긴/짧은/복면]·숏 케이프·림라이트 색) → `CharacterComposer`가 포즈 테이블(`poses.ts`)을 래스터화.
  부위는 머티리얼 ID로 그린 뒤 일괄 셰이딩: 정면 상단 키 라이트, 뒤쪽 실루엣 림라이트, 머티리얼 색으로 물든
  셀아웃 외곽선, 코트 자락·스카프·케이프의 2차 모션(천 펄럭임). idle(8)·run(10)·jump·apex·fall·land·skid.
  플레이어 = 승인 디자인 A "방랑자"(`PRESET_WANDERER`). 프리셋 B 탐험가·C 그림자 순례자와
  `randomAppearance(seed)`로 AI 모험가마다 실루엣까지 다른 외형을 에셋 없이 생성합니다(PHASE 4).
  표현 기법은 시네마틱 픽셀 액션 게임을 참고했지만 캐릭터 디자인은 오리지널입니다.
- **타일셋**: 레시피(soil/grass/stone/mossy/platform/planks/wall/beam) × 마스크 16 × 변형 3 + 프린지.
- **오브젝트**: 참나무·소나무(블롭 캐노피 방향광), 덤불, 풀·긴 풀·꽃(바람 흔들림 4프레임), 바위, 버섯,
  모닥불(6프레임 불꽃), 표지판.
- **배경**: 주기형 노이즈로 가로 타일링되는 원경 설산·중경 산·원경 숲·근경 숲, Bayer 디더 대기 원근,
  구름·해·달·별.
- **색**: 색조 이동(hue-shift) 셰이딩 — 그림자는 청보라, 하이라이트는 노랑 쪽으로.
- **몬스터·전투 아트(PHASE 3)**: 법선 재구성 볼륨 셰이딩(`shadedBlob`, 초타원·면 분할로 바위/갑옷 질감),
  선택적 외곽선(sel-out). 슬라임(스쿼시·스트레치), 딱정벌레(6다리 보행), 박쥐(날갯짓), 도깨비불(발광, 조명 기여),
  골렘(96px 보스). 무기·방어구·물약·재료 아이콘, 스킬·상태 아이콘(24/16px), 투사체·궤적·타격·폭발·서리·
  빛기둥·데미지 숫자 글리프. 손그림 교체 규약: 몬스터 프레임 `${monsterId}:${anim}_${i}`(텍스처 `monsters`).

손그림 교체: 같은 텍스처 키와 프레임 이름(`run_0`…, `tree_oak_0_0`…, 타일 프레임 인덱스 규약)으로
아틀라스를 `BootScene.preload()`에서 로드하고 해당 생성 단계를 건너뛰면 됩니다.

## 10. UI

React 19 + 순수 CSS 디자인 시스템(토큰: `ui/styles/index.css`). Galmuri 픽셀 폰트(OFL).
상태 표시(초상화는 캐릭터 스프라이트에서 자동 생성), HP/MP/EXP, 스킬 바·버프 바·보스 바·사망 화면,
캐릭터(스탯 분배·전직)·스킬·전직·인벤토리(장비 칸) 창, 미니맵(실제 월드 데이터, 3Hz),
시계/일차, 지역 배너, 채팅(로컬)·시스템 로그·개발 명령, 퀵슬롯, 메뉴 바, 드래그 가능한 창
(캐릭터 정보·설정·조작법·모험가 명부·모험가 정보 카드), 일시정지 메뉴, 로딩/타이틀/오류 화면. 단축키는 `InputManager.onUiAction`.

> 메뉴를 열어도 월드는 멈추지 않습니다 — 영속 온라인 월드를 전제로 한 설계입니다(입력만 차단).

## 11. 향후 구조 (계획 — 아직 구현되지 않음)

```
apps/server (PHASE 6)     Node.js + TypeScript + WebSocket 게이트웨이, 존(zone) 시뮬레이션 프로세스
  ├── sim                 packages/shared 시뮬레이션의 권한 있는 실행, 입력 검증
  ├── persistence         PostgreSQL (계정·캐릭터·수정된 청크·경제), Redis (세션·프레즌스·큐)
  └── economy             거래소·상점 — 모든 거래 서버 검증, 아이템 복제 방지
packages/shared/src/ai    (PHASE 4 구현됨) PHASE 5에서 AI 간 대화·파티·길드·거래·경제 계층 추가
packages/llm (선택)        LLM 대화 어댑터 — 별도 모듈, 게임 상태 직접 수정 불가, 사용자 승인 전 연결 금지
```

### AI 기능 도입 정책

외부 LLM/AI API는 **사용자 승인 없이 연결하지 않습니다**. 필요 시 목적·모델·예상 비용·대체 가능성·성능 영향을
먼저 보고합니다. AI 모험가의 이동·전투·채집·제작·성장·거래는 외부 API 없이 자체 게임 로직으로 구현합니다.
현재(PHASE 4)까지 어떤 외부 AI 서비스·LLM도 연결되어 있지 않습니다.
