PHASE 1의 **임시/제한 사항**

- 모든 그래픽은 절차적 생성(교체 가능 구조). 손그림 아트는 아님.
- 퀵슬롯·인벤토리·스킬·퀘스트·월드맵 버튼은 자리만 있고 잠금 상태.

- (PHASE 3에서 해결) HP/MP/EXP가 변하지 않음 → 전투·레벨업 구현.
- (PHASE 2에서 해결) 월드 변경 저장 없음 → IndexedDB 저장·청크 언로드 구현.
- 사운드 없음.

- 사운드(타격음·스킬음): 오디오 시스템이 아직 없음.
- 몬스터 아트는 절차적 생성(교체 가능한 아틀라스 규약) — 손그림 교체는 아트 파이프라인 단계에서.

- LLM 대화: 사용자 승인 전에는 도입하지 않음(AI 기능 도입 정책). 대사는 성격·상황별 템플릿.
- 추상 시뮬레이션의 단순화: 원거리 모험가는 지표 높이로만 이동하고 채굴·사냥 결과는 통계적으로 계산(청크 생성
  비용 회피). 화면 근처로 오면 완전 시뮬레이션으로 전환.
- 장시간 플레이 밸런스(모험가 성장 속도·사망률)는 아직 장기 테스트 전.

PHASE 5에서 **의도적으로 미룬 것** (이유)

- 서버 검증 거래: 모든 거래는 공유 코드에서 원자적으로 검증되지만 지금은 브라우저 로컬 실행 — PHASE 6 서버에서 같은 함수를 권한 있게 실행.
- 아이템 개별 데이터(강화·옵션·제작자 이름): 인벤토리 구조 확장이 필요해 장비 강화와 함께 진행.
- 퀘스트·NPC 의뢰: 메뉴의 퀘스트는 잠금 유지(PHASE 6 이후 콘텐츠 단계).
- AI 건축(집·거점 짓기): 건축 계획·재료 확보 로직이 커서 후속 작업.
- LLM 대화: 사용자 승인 전에는 도입하지 않음. 대화는 상황·관계·말투별 템플릿과 자체 규칙.
- 장시간 경제 밸런스(인플레이션, 시세 안정성)는 장기 테스트 전 — 골드 소모처(수수료·상점·길드 창설) 외 추가 소모처 검토 필요.

승인된 범위: 로컬 Docker/compose + CI만(유료 배포 없음), 이메일+비밀번호 계정(이메일 인증 없음), 오프라인 모드 유지,

PHASE 6에서 **의도적으로 미룬 것** (이유)

- 실서버 배포·도메인·TLS: 유료 인프라는 사용자 승인 사항. compose로 로컬 실행까지 검증.
- Redis·다중 서버(존 분할): 승인된 규모(1대·100명)에 불필요 — 필요해지면 세션·프레즌스부터 도입.
- 이메일 인증·비밀번호 재설정: 메일 발송 서비스(외부·비용) 필요 — 승인 후.
- 스냅샷 델타 압축: 밀집 최악 경우 클라이언트당 약 178KB/s. 일반적인 분산 플레이에서는 훨씬 적지만, 대규모 공개 전 델타/양자화 필요.
- 전투 행동 예측: 공격·스킬 모션은 서버 확인 후 표시(왕복 지연만큼 늦음). 이동은 예측됨. → PHASE 7에서 해결.
- 원거리 파티원 상태: 관심 영역 밖 플레이어 파티원의 HP는 표시하지 않음.
- 관리 도구(운영자 패널·제재·로그 조회): 저널·로그는 쌓이지만 UI는 다음 단계.
- PvP: 승인 범위 밖.

PHASE 7에서 **하지 않은 것**

- 무작위 옵션·제작자 이름 같은 아이템 개별 속성: 강화 수치만 개체별로 저장(구조는 확장 가능).
- 강화 장비의 거래·판매: 귀속으로 막음(거래소의 아이템 모델이 id+개수라서). 필요해지면 개체 단위 거래로 확장.
- 액체의 수평 퍼짐(수위 맞추기): 떨어지고 옆으로 미끄러지는 흐름만.
- AI 모험가의 새 지역 원정: 마을 주변 위주로 생활(새 몬스터 재료가 필요한 장비는 거의 만들지 않음).
- 예측이 서버와 어긋날 때(예: 서버에서만 막힌 스킬) 잠깐 보이는 동작은 되돌리지 않음.
